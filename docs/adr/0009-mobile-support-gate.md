# Mobile-Support (Runde 5): Plattform-Gate für Node/Electron-Features

Kontext: Obsidian Mobile (iOS/Android) hat kein Node-Environment. Das Plugin hängt an mehreren Stellen an Node/Electron: der `IServClient`-Default-Transport importiert Node `https`/`http` (crash beim Bundle-Laden auf mobile), `safeStorage`-Keychain für Credentials, `Buffer` in `src/api/mails.ts` (Base64-Decode), `src/review-queue/files-feed.ts` (Base64-IDs) und der Login-Content-Length-Header. Vault-only-Features (Review-Queue-UI aus `queue.json`, GradeStore aus `data.json`, StudyPlan-Note, NoticeCenter, PDF-Preview via Obsidian-Bundle) sind dagegen mobile-tauglich.

Entscheidung: Einstieg = Gate, kein Transport-Umbau. Ein injectable Platform-Wrapper (`src/mobile/platform.ts`, Node-Testbar) plus eine Feature-Map (`src/mobile/guard.ts`) definieren, was Node/Electron braucht: Sync-Ribbon/Command, JobRunner-Polls (keine Intervall-Registrierung auf mobile), Mail-Sync-Client-Requests, Credentials-Modal, Battle-Test. Gesperrte Aktionen auf mobile antworten dezent über NoticeCenter `notifyOnce` ("Funktion benötigt Desktop (Netzwerk)") statt zu crashen. Startup-Auto-Login und Cred-Retry-Timer laufen nicht (Node-Login + safeStorage). Auf mobile bleiben die UI-Views mit bereits geladenen Daten aktiv. Der IServClient bleibt unangetastet — der ADR-0005-Transport-Seam ist der spätere Einstieg für einen fetch-basierten Transport-Umbau.

Konsequenzen: Sync veraltet auf mobile bis Daten per Desktop-Sync ankommen — Views zeigen den letzten `queue.json`/`data.json`-Stand. `Buffer`-Nutzung bleibt (esbuild ersetzt in mobile-Build pollyfilled? nein — crasht erst zur Laufzeit, follow-up: Login-Body-Content-Length und Mail-Base64 sauber austauschen). Follow-up nach iOS-Test eines fetch-Transports: Buffer-Ersetzungen, Credential-Strategie auf mobile (safeStorage fehlt), JobRunner-Polls re-enable.
